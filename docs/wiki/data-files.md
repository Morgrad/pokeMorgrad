## Static game data and priors

**`regmc_db.json`** - Showdown dex export for the Reg M-C format (built 2026-10-11 per `meta.built`). Top-level keys (verified by grep): `meta`, `rules`, `natures`, `types`, `typeChart`, `items`, `moves`, `abilities`, `species`. `meta` example: `{"format":"gen9championsvgc2026regmc","mod":"champions","built":"2026-10-11T03:52:08Z"}`. `rules` has `gameType: doubles` and ruleset `Flat Rules, VGC Timer, Open Team Sheets`. Read by `src/regmc_db.py:18` (and through it `damage.py`, `ga_core.py`, `state_encoder.py:34`, `opp_model.py`). The `immune` type-chart code is 3 (fixed in commit f9c354c).

**`species_build_priors.json`** - `{species: [{"evs": {...}, "nature": str, "count": int}, ...]}`, most common first. Example: `"Absol": [{"evs":{"atk":32,"hp":2,"spe":32},"nature":"Jolly","count":2}]`. Also has `"Species @ Item"` keys when >=3 teams. Source: VGCPastes teams. Read only by `src/opp_model.py:63` (opponent build mixture for DoublesPilot, top-K=3). Must exist at battle time with `--pilot doubles`, yet it is untracked in git.

**`species_ability_priors.json`** - `{species: [{"ability": str, "count": int}, ...]}`. Example: `"Aegislash": [{"ability":"Stance Change","count":2}]`. Read by `src/opp_model.py:69`.

**`species_move_priors.json`** - `{species: [{"move": str, "count": int}, ...]}` (top 30 per species from ladder replays, or top 20 from tournament teams). Example: `"Gholdengo": [{"move":"Shadow Ball","count":867},...]`. Counts of 867 etc. show this on-disk version is replay/ladder-derived (identical to `.ladder.bak.json`); the tournament regeneration is pending. Read by `src/bc_train.py:28` and `src/bc_player.py:34` (BC legality mask). `tools/preflight.py:55` checks it exists.

**`meta_items.json`** - `{species: [{"item": str, "count": int, "pct": float}, ...]}`. Example: `"Excadrill": [{"item":"Focus Sash","count":21,"pct":91.3}, ...]`. Read lazily by `src/ga_core.py:142-153` (`meta_items_for`, weights item draws). Generator unclear: no script writes it.

## Team pools and splits

**`regional_teams/`** - Showdown-format team text files, one team each. 350 `.txt` by prefix: `vgc_*` 150 (VGCPastes, current train), `real_ev_*` 100 (current holdout), `baltimore_*` 22, `frankfurt_*` 34, `louisville_*` 26, `brisbane_*` 9, `recife_*` 9 (100 Limitless tournament teams on disk). Subdirs: `_archive_2026-10-15/` (445 old train files moved by `swap_pool.py`), `_rejected/` (currently empty; `normalize_tournament.py` moves unfixable files here). The 100 tournament-prefixed files are NOT in `pool_split.json` yet (they need `extend_train_pool.py <prefix>` per prefix). Note `src/ga_core.py:119` globs this directory; split entries are resolved by basename against this directory (ga_core.py:160).

**`pool_split.json`** - `{"train": ["vgc_MC210.txt", ...], "holdout": ["real_ev_000.txt", ...]}`. 150 train, 100 holdout (lines 3-152 and 155-254). Read by `ga_core.regional_pool()` (line 187) and `heldout_pool()` (line 217), hence by eval, GA, pilot tools. In the GA the train pool is further cut into train and a 30-team validation slice (`VAL_POOL_SIZE`, seed 42; ga_core.py:70,202,1449).

**`pool_split_golden.json`** - the original frozen holdout (550 lines; uses a longer path format). `extend_train_pool.py` compares the current holdout against it. Note the current `pool_split.json` holdout (`real_ev_*`) is NOT the golden holdout, so that script's golden check will warn.

**`.bak` files** - `pool_split.json.bak` equals golden (md5); `pool_split.mixed_holdout.bak` is the split before the real-EV holdout swap.

**`baseline_team.txt`** - the hand-built Umbreon-lead seed team (Showdown paste format). Read by `src/eval.py:87` (default team), `run/ga_run.py:20`, `run/ga_island.py:42` (island A seed), `src/regmc_db.py:391`, `src/showdown_validator.py:52`, `src/audit_before_launch.py:181`, `tools/pilot_probe.py`, `tools/bc_diagnostic.py`.

## Replay and training data

**`showdown_replays/`** - `<format>-<id>.json` (full replay with log) plus `<id>.meta.json` (`{"rating":1446,"uploadtime":1789066747}`), ~5,006 replays. Raw log is in the `log` field. Written by `scrape_replays.py`; read by `build_training_data.py`.

**`showdown_replays_meta/index.json`** - list of `{"id","rating","uploadtime","players":[a,b]}`. Scraper index; resumable state for `scrape_replays.py`.

**`replays/`** - `regmc_replays.jsonl` (5,100 lines: `{"id","format","players","log",...}`) and `parsed_replays.jsonl` (4,952 lines: id, rating, p1/p2 names and teams, winner). Produced by `archive/one_offs/download_replays.py` and `parse_replays.py`; only consumers are archived scripts (`archive/old_bot/*`). Effectively dead data kept on disk.

**`training_data*.jsonl`** - one JSON object per decision point (one side, one turn). Keys: `replay_id, rating, turn, side, state{my_active, my_bench, opp_active, opp_seen, field}, legal_actions, chosen, side_won, target_a, target_b`. Tiny example (truncated): `{"replay_id":"gen9championsvgc2026regmc-2678861791","rating":1446,"turn":1,"side":"p1","state":{"my_active":[{"species":"Salamence","hp_now":100,"revealed_moves":["Hyper Voice","Protect"],...}]}`. Readers: `src/bc_train.py:27` (default `training_data.jsonl`, override with `BC_DATA`), `tools/build_species_priors.py`, `tools/encode_snapshot.py`. The three `_heuristic*` variants are heuristic-pilot imitation sets selected via `BC_DATA`.

Champion semantics, per code (`src/ga_core.py:1542-1556`): the un-suffixed file is written from `best_ever` (training-best) whenever it exists, falling back to `best_val_ever`; the `_train` file is always `best_ever`. So the two are normally identical, although comments and OPERATIONS.md call the un-suffixed one "val-selected". Verify before relying on it.
