## What this project is
pokeMorgrad searches for a strong Pokemon VGC team for the format `gen9championsvgc2026regmc`
(Regulation M-C, Champions mod, doubles). A genetic algorithm (GA) evolves 6-mon teams; each
candidate team is scored by playing real battles on a local Pokemon Showdown server through
poke-env, with a rule-based pilot (`VGCPilot`) for our side and `LadderOpponent` for the
opponents, against a pool of real tournament teams. Champions are re-scored on a held-out pool.
A second track trains a behavior-cloning (BC) neural pilot from human replays (weaker than the
rule-based pilot today; kept as a foundation for future search/RL).

## Format facts (always true, never "fix" these)
- Doubles. Mega Evolution legal. Terastallization NOT legal: never write Tera logic.
- EVs are Champions-style points: 0-32 per stat, 66 total; stat term `max(2*pts-1, 0)`.
- Showdown is the source of truth for legality: `data/regmc_db.json` is generated by
  `node tools/build_regmc_db.js`; never hand-edit it. Never modify `~/pokemon-showdown/`.

## Hard rules
1. Discuss / propose before editing when asked to analyze. Follow `.clinerules/00-core-rules.md`
   (backup -> edit -> `ruff check --fix <files>` -> `bash tools/verify.sh` -> restore on failure).
2. The gate is `bash tools/verify.sh`; it must print `ALL PASS`. Anything else = not done.
3. Held-out pool is sacred: fitness uses `pool_split.json["train"]`; final scoring uses
   `["holdout"]`. Never feed holdout teams to the GA.
4. Never launch long jobs (GA runs, paired evals, BC training, scrapers) without the user's
   explicit go-ahead (hours + run_id). Unit tests must not need Showdown or network.
5. GA behavior is pinned by a golden master (`tests/test_ga_golden.py`). If it fails after a
   change that was supposed to be a pure refactor, the refactor is wrong. Regenerate the golden
   file ONLY for an intended behavior change, and say so in the commit:
   `PYTHONHASHSEED=0 python tests/golden/ga_harness.py --write`.
6. `data/*` is gitignored except a whitelist (see `.gitignore`); new data files need `git add -f`.
7. Plain ASCII in code, docs and output; no emoji.
8. Never overwrite `output/models/bc_best.pt` without a 5-seed eval showing +3 pts.

## Environment and commands (repo root = `~/pokeMorgrad`, inside WSL2 Fedora)
```
source .venv/bin/activate            # or: source ~/venv-pokemorgad/bin/activate (original workstation)
bash tools/verify.sh                 # full gate: ruff, imports, pools, all tests, audit -> ALL PASS
python tests/test_damage.py          # one test file (prints PASS/FAIL per test)
ruff check --fix src/x.py            # lint before verify
python -m src.audit_before_launch    # data integrity + fuzz legality (~15 s)
python tools/preflight.py            # pre-launch checks for a GA run
```
Showdown servers: `~/pokemon-showdown`, ports 8000-8002 (`docs/runbooks/showdown.md`).
GPU: AMD 7900 XTX (ROCm). The GA is CPU-bound; BC training needs the GPU - do not train BC while
a local LLM holds the VRAM (`docs/runbooks/environment.md`).

## Saving context (important for small-context models)
- Do NOT open these whole: `data/regmc_db.json` (1 MB), `tests/golden/ga_golden.json` (450 KB),
  `data/species_*.json`, anything in `archive/`, `output/`, `docs/history/`.
  Use `grep -n` / `python -c` to pull the piece you need.
- Find code by symbol: docs cite `path::symbol`; run `grep -n "def symbol" -r src`.
- Biggest source files: `tools/replay_tracker.py` (625 lines), `src/turn_sim.py` (434),
  `src/bc_train.py` (405), `src/ga/genome.py` (398). Read them by function, not whole
  (`grep -n "def " <file>` for the outline).
- `.clineignore` keeps Cline from reading `data/` big files, `output/`, `archive/`,
  `docs/history/`, `.venv/` and the golden fixture. Query those from the terminal.
- Current status and next steps: `docs/STATE.md` (short). Full history: `docs/history/` (only when
  asked about the past).
